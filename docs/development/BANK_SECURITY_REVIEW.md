# 银行原型安全自评（开发稿，非第三方认证）

> 体验入口见 [仓库首页](../../README.md)；本文供开发、测试与安全审阅使用。

评估日期：2026-09-26。范围为独立 `/bank-agent` 页面和 `bank-server.js`，不为旧 UniTally 登录/云数据库功能背书。必须本机运行，禁止直接按此配置公开部署。

## 可信边界

1. 浏览器持有虚构会话随机令牌，后台核对归属；不是现实身份或完整登录系统。XSS或本机恶意进程获取令牌的风险仍存在。
2. 模型只提出白名单工具草案，不执行支付，不决定风险等级，不提供真假银行事实。
3. 所有写操作经服务端校验、不可变草案、明确确认；红级再核验OTP演示或已注册Passkey设备签名。
4. 基本金额全部整数分。资金变化由确定性程序、预留检查和双边记录实现；工作流按实际任务结果推进。
5. 模型、手工WAT、商户备注等不可信内容都没有任意shell、文件或银行调用权限。

## 明确剩余风险与不适用场景

- 无真实银行接入、支付牌照、金融合规认证或银行实名核验。不能接收真实资金或真人敏感材料。
- 默认屏幕OTP仍是演示；Passkey首次注册证明设备控制，不证明真实身份，且没有凭据恢复/迁移。
- JSON账本供本地开发：只支持所有写者都采用同一锁协议。旧进程与新进程混跑可破坏保证；Windows目录刷盘限制意味着不能保证硬件掉电绝对持久性。
- 审计记录可追溯但不是不可篡改的外部审计账本；本机管理员可以改数据。尚未全量硬件故障注入。
- 隐私筛查是启发式，不能保证识别所有个人信息。真实AI模式会向DeepSeek发送当前需求、最近部分对话和白名单模拟对象引用；用户不得输入真实个人信息。没有宣称供应商零留存。
- 模型的安全拒绝不是唯一防线；后端控制仍需存在。少量开发样本与测试替身不构成综合越狱安全认证。
- Wasmtime运行时及Python本身可能存在未发现漏洞。限制的是线性内存及指令预算，并非整个进程硬性RSS容器隔离；i64计算会溢出环绕，禁止直接用作账务决策。当前未接实时模型生成代码。
- 预约只到期提醒并重新授权，不是自动扣款；商户/会员取消/理财赎回均为明确模拟；卡片渠道策略尚无真实支付渠道执行证据。
- 依赖仍有npm已报告问题：本次后端20、前端29条包级告警；旧Firebase链和开发工具的风险需分批迁移，不能称“全仓安全”。
- 手工表单/离线案例与自然语言路径都走同一权限后端，但新增场景的真实模型解析质量未全部验证。

## 交付前必须继续做

新增场景的固定开发评测、独立保留集；模糊否定/跨轮改条件/工具返回注入；独立用户体验；真人设备注册；团队源码审阅；官方验收口径与提交材料确认。保留失败证据，不能仅用页面数量或单元测试数量证明最高奖水平。
