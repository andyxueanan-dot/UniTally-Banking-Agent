## 先体验

双击 `启动银行智能体.cmd`，或打开 **http://localhost:5091/bank-agent**。与旧的 `127.0.0.1` 地址不是同一浏览器存储来源，首次打开会建立独立虚构会话，不会自动迁移账户令牌。

1. 工作台：查看消费分类图，点击分类筛选账单；让助手分析，再展开异常候选两条原始交易。
2. 转账：准备 200 元转账，确认前余额不变；改需求使旧草案失效；完成后查看回执。保留余额条件由后台重检。
3. 服务中心 → 订阅与代扣：先确认查询，再分别撤销银行代扣或终止商户会员，两者不混称。
4. 服务中心 → 模拟理财：手动回答三个教学问题，再比较虚构产品、申购及按实际持仓赎回；不生成收益，不作投资建议。
5. 扩展卡服务：DEMO 虚拟卡、临时锁定/解锁、渠道限制、额度申请。额度申请只记录待审核，不直接授信。
6. 多步协作：运行固定案例，体验逐项确认、暂停、恢复、取消剩余步骤、本地接管记录；已完成转账不会被伪装成整体回滚。
7. AA 与生活计划：明确本人是否参与 AA；预约只创建提醒；预算先预留再逐项创建订单、付款、释放余款。全部商户、对手资金与交易均虚构。
8. 计算沙箱：执行预置加法/分摊算式，或无限循环被指令预算拦截。结果是低信任计算记录，不是银行回执，不能直接写账。

业务表单和固定案例都可离线使用，并明确不调用 AI。自由聊天需要自己的后端密钥；新扩展场景的模型规划准确率尚未完成真实 API 评测，不要把表单验收称为模型测试。

## 可选设备验证

在服务中心明确勾选同意后，可以给此虚构会话注册一个 Passkey（通行密钥）。它使用真实 WebAuthn 签名验证，注册后红色操作不能再降级到页面演示验证码。浏览器会调用设备能力，如 Windows Hello 或安全密钥；真实设备注册要由用户亲自操作。

这不是银行实名/KYC，也不是支付行业合规认证。系统设备弹窗不保证显示金额和收款人，必须先在网页核对详情。测试使用了 Chrome 虚拟认证器进行真实协议验签，不代表已亲测真人 Windows Hello。不支持注册后任意换设备或自动重置凭据。

## 计算运行时安装

普通银行场景只需 Node；代码计算沙箱另需本机 Python 与专用环境。在 UniTally 仓库目录执行（Windows）：

```powershell
py -3 -m venv .venv-sandbox
```

```powershell
.\.venv-sandbox\Scripts\python.exe -m pip install -r sandbox-requirements.txt
```

实际锁定 Wasmtime 49.0.0；本机已经装好，其他队友需自行安装。该目录被 Git 忽略。没有运行时会明确提示不可用，不回退到不安全的 Node `vm`。

限制：独立子进程、无任何外部导入/WASI/宿主函数、128 KiB 线性内存、50,000 fuel、2.5 秒时限、并发 2；固定 `calculate(i64,i64)->i64`。64位溢出会环绕，结果始终 `trustedForLedger=false`。这不是完整操作系统容器，运行时本身的漏洞仍是风险；当前仅手工/预置 WAT，没有实时模型生成代码流水线。

## 官方赛题对照

来源为 2026-09-26 实际读取的[官网赛题](https://fintechathon.g-ican.com/#/)与[规则](https://fintechathon.g-ican.com/#/rule)。评分：任务完成 40%、安全合规 30%、创新及交互 30%。六类至少覆盖三类是最低要求，表格中的具体功能为参考，本轮仍尽量扩展覆盖。

| 方向 | 已实现的可测试原型 | 不能宣称已经做到 |
|---|---|---|
| 转账 | 姓名/别名/备注/专用000开头虚构号码检索；精确分币；AA请求/显式模拟入账；超时预留和对账 | 真实银行手机号收款；真实他人付款；无需再确认的自动定时扣款 |

| 理财 | 虚构产品对比、教学风险问卷、申购/到期赎回及本金双边记账 | 专业适当性评估、收益预测、真实产品或真实投顾 |
| 卡片 | 挂失/解挂、临时锁定/解锁、消费限额、DEMO虚拟卡、渠道限制、待审核额度申请 | 真实支付卡号、已获信用额度、真实银行消费授权接口 |
| 订阅/代扣 | 依题目黄色查询确认；已知模拟授权与疑似扣款区分；预计续费；分范围取消 | 真实商户会员取消、自动退款、仅凭一次消费确认周期合同 |
| 跨场景 | 显式预算目标、预留资金、虚构花/蛋糕报价、订单草案、逐项付款、未用金额释放 | 自动读取私人日历、真实配送、无监督自动购物、已付款自动回滚 |
