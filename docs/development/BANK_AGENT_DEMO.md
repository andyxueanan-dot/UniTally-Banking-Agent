## 怎么打开

浏览器访问 **http://localhost:5091/bank-agent**（可选设备验证需要 localhost；旧IP地址使用独立浏览器会话）。

本机已安装和构建过的同学，可双击本目录的 **启动银行智能体.cmd**。脚本会检查本机服务、必要时启动，并打开浏览器。服务只监听本机，不向公网开放；没有计划任务或开机自启。**首次从 GitHub 下载的队友，请先完成下面的安装步骤**：依赖、构建产物和私有密钥均不随仓库上传。

## 队友首次运行

建议使用 Node.js 24（本版实测 24.14.1）。在希望存放项目的位置打开终端，执行：

```powershell
git clone https://github.com/andyxueanan-dot/UniTally-Banking-Agent.git UniTally-bank-agent
```

```powershell
cd UniTally-bank-agent
```

```powershell
npm ci
```

```powershell
npm --prefix backend ci
```

```powershell
npm run build
```

```powershell
node backend/bank-server.js
```

保持最后一个终端运行，浏览器访问 http://localhost:5091/bank-agent 。Windows 也可以在安装后改用「启动银行智能体.cmd」。不需要 Firebase、MongoDB 或真实银行账号来运行这个独立页面。代码计算沙箱另需专用 Python 环境，准确安装命令见 [运行时安装](BANK_QUALITY_PROGRESS.md#计算运行时安装)；不安装也能使用其他银行模拟业务。

**没有密钥也能体验**：默认进入明确标注的离线固定案例，点击三个场景即可。若要自由对话，在本机将 `backend/.env.bank.example` 复制为 `backend/.env.bank.local`，填入自己有权使用的 `DEEPSEEK_API_KEY`，再重启后台。不要把密钥写进源码、提交到 Git，或发到团队群；这里不会分发作者的私有密钥。真实模型调用可能产生费用。

仓库已有副本的同学先保存自己的改动，再 `git fetch origin` 并切换到该分支；不要通过覆盖目录或强制重置来更新。大家后续各自建功能分支，通过 Pull Request（合并请求）审阅后再合并。

## 5 分钟体验

1. 点击「我的钱花在哪了？」：DeepSeek 解析需求，后台对 14 条虚构本月账单精确求和。应得到 ¥1,125.00，上月 ¥514.00；同日同商户的两条咖啡消费被标为待核对，而不是断言重复扣款。
2. 点击「给小王转 200 元」：确认前余额仍为 ¥12,860.00；勾选核对详情、点击确认执行后变为 ¥12,660.00，收款方也被记账，生成唯一回执。该转账不会被混入消费统计。
3. 点击「找不到我的消费卡了」：确认尾号 8806，点击「获取演示验证码」，手动填入页面显示的 6 位码，勾选并确认。卡片从正常变成「已挂失冻结」。验证码是演示，不是真实短信/人脸/多因素认证。
4. 点击「同名收款人」：有两位陈晨，系统必须追问尾号 3801 或 9526，不能猜。
5. 点击「模拟接口超时」并确认：金额先预留，显示待对账，没有成功回执。点击「模拟后台对账」才完成一次记账；不会因重复确认扣款两次。
6. 左侧「操作记录」可以查看并导出任务、回执和双边记账记录；刷新网页能恢复当前会话。

也可以自由输入：

- 「给王明转两百元，先让我确认」
- 「查询我的余额」
- 「把 6219 卡的每日消费限额改成 500 元」
- 「解挂恢复尾号 8806 的卡」
- 「不要给王明转 200 元，只查询余额」

需要从头演示时，右上角创建「新演示账户」。旧会话保留在本地文件中，但当前浏览器会切换令牌；先导出需要的记录。

## AI、数据与资金各自是什么

- **真实 AI**：后端调用 DeepSeek 的结构化工具规划。此次实际响应的模型名称是 `deepseek-flash`，请求使用 `deepseek-chat` 别名；界面每条消息记录实际响应耗时和 token 数。
- **真实运行的程序逻辑**：金额计算、余额检查、日累计权限、草案绑定、确认、任务验证码、资金预留、幂等、对账、回执、文件持久化。
- **完全虚构**：账户、联系人、历史账单、卡片、验证码与所有资金；没有银行接口、银行卡扣款或真实短信。
- **离线演示**：切换后只运行明确标注的固定案例，不能自由理解输入，也不会伪装成 AI 回答。
- 真实 AI 模式会把输入及最近少量对话发往 DeepSeek，请只输入虚构信息，不填真实账号、身份证、手机号、密码或隐私材料。后端会拦截部分明显的密钥/长账号，但该检测不是完整的个人信息识别系统。

API key 仅存于后端 `backend/.env.bank.local`，已被 Git 忽略，前端和审计导出不包含它。一天最多 80 次模型调用尝试，每个会话每分钟最多 20 次；不是金额预算，费用以供应商账单为准。空闲时不自动调用模型。

## 现在还不是什么

不是生产银行认证、正式审计系统或最终参赛成品；没有真实银行接入、AA 收款、定时业务、理财产品、语音输入或跨币种操作。一次只准备一项写操作，可伴随查询；不是通用复杂任务图执行器。仅开放固定业务工具，不执行模型生成代码。文件存储用于单进程本地演示，不是金融级数据库与不可篡改审计。

暂未做用户访谈、全面对抗测试、正式独立评测或大样本意图准确率统计。接下来应先收集团队的真实体验反馈，再补官方规则核验、场景深度和评测集。

## 开发与复测

新版共享工作分支：`feat/bank-agent-quality`（此前三场景版为 `feat/domestic-bank-agent`）。本版用于队友查看和本地体验，不直接合并 `main`。它保留上一版学费沙箱作为工程基础，当前国内银行原型的独立入口是 `/bank-agent`。

在 UniTally 目录运行：

```powershell
node scripts/check-bank-project.mjs
```

```powershell
node scripts/check-bank-browser.mjs
```

第二条需要先启动服务，并在 Windows 默认位置安装 Google Chrome；默认离线测试，不产生 AI 费用；加 `--live` 会调用 4 次 DeepSeek。`node scripts/check-bank-ai-safety.mjs` 另调用 2 次。`node scripts/check-bank-restart.mjs` 使用隔离临时数据和 5093 端口，不调用 AI。测试结果写入仓库上一级的 `evidence/T002/`。`snapshot-bank-handoff.mjs` 是作者本机交付清点脚本，依赖本地密钥和历史证据，不是队友首次运行所需步骤。

改代码后先运行 `npm run build`；后台逻辑或密钥变化需要重启仅属于本项目的 `backend/bank-server.js` 进程。勿批量结束所有 Node 进程。

实现时参考：[DeepSeek 官方工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)。实际接入是否成功以本轮真实响应证据为准。
