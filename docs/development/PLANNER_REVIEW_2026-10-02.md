# 同学反馈处理：日期、模型来源与纠错

## 1. 日期与时区

`toISOString()` 始终输出 UTC，不取决于进程部署地。原有账本月份、日累计计算本已显式使用 UTC+8；这次主要补的是模型输入歧义及模型日期参数的后端核验，而不是声称整个系统此前都有八小时偏移。

新增 `backend/bank/calendar.js`：输出UTC时刻/日期、北京时间/日期，程序生成前天/昨天/今天/明天/后天对照表，以及本周和上周范围。周一为一周开始，UTC查询边界左闭右开；不依赖宿主机TZ。

- 新账单期间键：today、yesterday、day_before_yesterday、this_week、last_week。由代码选择记录，模型不提交算出来的日期。
- 日期消歧或多个相对日期暂时追问，不随便替换成一个查询范围。
- 相对日期预约要求 `relativeDateKey` 和明确的 `localTime`，后台换算为 `+08:00` ISO，再保存 UTC 时间戳。只有“明天早上”会追问；当前仅明确数字时刻可转换，中文数字、半点和复杂口语可要求24小时格式确认。
- 模型把日期范围提错、把历史查询变成立即转账、或规划期间跨北京时间午夜，均停止新操作。
- 定时业务仍是提醒及到时再次确认，不是后台自动付款。

## 2. 模型供应商可配置，但不做隐形备用

保留 DeepSeek 默认配置；新增 OpenAI-compatible 工具调用接口，可用下列后端环境变量明确选择：

| 变量 | 用途 |
|---|---|
| BANK_AI_ENDPOINT | 完整 chat/completions HTTPS 地址 |
| BANK_AI_API_KEY | 此供应商专用密钥；不会把旧DeepSeek密钥自动转发给新域名 |
| BANK_AI_MODEL | 明确模型名 |
| BANK_AI_PROVIDER | 用户可见供应商标签 |
| BANK_AI_MAX_PROMPT_CHARS | 提示词字符预算，默认24000；不是token计数 |
| BANK_AI_ALLOW_LOCAL | 仅显式设置true时允许回环HTTP本地模型；不会打开公网HTTP |

不自动切供应商，不自动换成规则回答。模型网络故障/拒绝时显示“AI暂不可用”；未配置、格式错误、真实工具规划、手工操作及离线案例保持来源区分。

历史上下文超预算时优先去掉最老历史，不截断最新需求、安全规则或日期表；仍超预算则拒绝发送。接口兼容不代表模型工具调用能力已经验证。

可选 `node scripts/probe-local-context.mjs --base=http://127.0.0.1:11434 --model=<名称>` 只读Ollama已加载模型的 context_length，不加载模型、不产生生成费用。当前未接入或验证本地模型，也未复制同学未提供的Mailigence源码。

## 3. 评测

`evaluation/bank-date-traps.json` 增加14条开发陷阱用例。`node scripts/evaluate-bank-full.mjs --temporal` 默认只校验集合、不调用API。真实模式新增“一次真实供应商调用”和“返回来源确为AI而非离线/手工”的断言。

之前批准的60次额度已经用完，**这轮没有新增真实模型评测**；不能用mock单测来宣称DeepSeek/Qwen已通过日期陷阱，也没有获得新的自动调用预算。

## 4. 错误回流

INVALID_AI_PLAN、跨午夜失效自动进入会话私有待审核队列；用户可以在AI回复下展开“理解有误？记录纠正”。纠正会使这条回复对应的未确认草案失效，已执行交易不被伪装成撤回。

队列最多100项，不自动删除、不跨会话共享；“我的 → 模型纠错记录”可导出。需要人工脱敏、审核、编写预期结果，再纳入评测。当前**没有自动few-shot注入**，防止错误样本、敏感资料和恶意指令进入系统提示。
