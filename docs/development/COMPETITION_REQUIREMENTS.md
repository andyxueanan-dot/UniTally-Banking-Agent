# 赛题要求落地对照（2026-10-09）

依据：《银行AI智能体.md》原文与官网规则（评分 40% 任务完成 / 30% 安全合规 / 30% 创新与交互）。每一行写"赛题要什么 → 我们怎么做 → 在哪里能看到 / 测到"。✅ 已实现并有测试；🟡 有实现但有边界，边界写在"说明"里；⬜ 未做。

## 一、六类场景

| 场景 | 赛题示例 | 实现 | 入口 | 测试 |
|---|---|---|---|---|
| 智能转账 | 人名 / 手机号 / 备注 / 定时 / AA | ✅ 人名、别名、备注、虚构手机号检索；同名追问；定时=到期提醒+重新确认；AA 请求与显式模拟入账 | 助手；首页"转账汇款"；更多服务 | `bank-recipient`、`bank-advanced-*` |
| 账单分析 | 分类统计、异常识别、月度/年度报告 | ✅ 分类与环比；异常三条规则（同日同商户同金额、新商户单笔 ≥ ¥300、同类 ≥ 3 倍中位数）；`bill_report` 月/年报告（类目占比、商户 Top5、转出/退回、订阅合计、提示） | 助手"月度报告"；说"这个月的账单报告"走规则快判 | `bank-analytics`、`bank-competition-gaps` |
| 理财操作 | 推荐对比、风险评估、申购赎回 | ✅ 三个虚构产品；苏州银行 V.202308 十一题测评；申购红色、到期赎回 | 更多服务 → 模拟理财 | `bank-business`、`bank-risk-questionnaire` |
| 卡片管理 | 申请、额度、限制、解锁、挂失 | ✅ 虚拟卡、日限额、线上/境外限制、临时锁/解锁、挂失/解挂（红色） | 卡片管理；更多服务 | `bank-business`、`bank-card-payment` |
| 订阅/代扣 | 识别、续费提醒、一键取消 | ✅ 流水识别、已知/疑似区分、预计续费日、分别撤销代扣/终止会员 | 更多服务 → 订阅与代扣 | `bank-business` |
| 跨场景联动 | "检测爱人生日 → 当月锁定 1000 → 生日前 2 天订鲜花蛋糕" | ✅ **检测**：账户里的重要日期（虚构）在首页显示"即将到来 · 爱人生日"；**一句话或一键**：`life_event_plan` 自动拆成 5 节点依赖图（锁定预算 → 鲜花、蛋糕两张订单并行 → 分别付款），节点之间传递真实的预算 ID、订单 ID；配送日 = 生日前 2 天；日期只从用户原话或已存日期读取，模型给错就停 | 首页"即将到来"；助手"生日联动"；说"下个月15号是我爱人生日" | `bank-competition-gaps`（全流程 5 次确认到付款完成） |

## 二、权限分级（由后端判定，模型不能降级）

| 级别 | 赛题 | 实现 |
|---|---|---|
| 绿 | 查询直接执行 | ✅ 余额、流水、分析、报告、重要日期、理财持仓、沙箱计算 |
| 黄 | ≤1000/日转账、订阅查询取消、虚拟卡 | ✅ 日累计在后端算；订阅查询也按黄色；撤回申请为黄色 |
| 红 | >1000、改密码、挂失解挂、申购 | ✅ 含**修改交易密码**（新密码只在页面输入，scrypt 加盐哈希，不经过对话/模型/日志）；🟡 线上为页面内演示验证码，本机可用 Passkey 设备签名 |

## 三、安全五条

| 条款 | 实现 | 测试 |
|---|---|---|
| 幻觉防护 | ✅ 余额、回执、结果全部来自后端；超时进"待对账"；撤回只说"已提交申请" | `bank-quality`、`bank-provider-feedback` |
| 注入防御 | ✅ 工具白名单 + 字段校验；33 条攻击集（29 条离线回放通过）；🟡 模型侧 live 评测待额度 | `bank-attack-set` |
| 操作审计 | ✅ 每个意图、草案、确认、执行、转人工、回退、熔断、沙箱代码（含 SHA-256）都写审计，可导出 | 各测试断言 audit 事件 |
| 异常熔断 | ✅ 连续 3 次验证失败锁 5 分钟；**新增行为规则**：10 分钟内向 ≥4 个不同收款人、同一人 ≥4 次、60 分钟内 ≥3 笔且 > ¥20,000、10 分钟内 ≥5 次被拦截（疑似试探）→ 锁 10 分钟、作废待确认草案、自动开风控工单；查询不受影响；客服核实后可解锁 | `bank-competition-gaps` |
| 沙箱（生成的代码在隔离环境运行） | ✅ **模型写代码 → 沙箱执行**：`sandbox_calc` 让模型写整数算式（AA 分摊、按比例分预算），后端用严格语法解析、编译成**无导入的 WebAssembly 模块**，在 Wasmtime 子进程里运行（指令预算、内存、时限、并发受限），结果只作参考、不入账，审计记录代码哈希；🟡 线上 Render 未安装 Wasmtime，会如实显示"沙箱未完成"，演示视频用本机录 | `bank-competition-gaps`、`bank-code-sandbox` |

## 四、意图理解与任务规划

| 条款 | 实现 |
|---|---|
| 模糊 / 省略 / 隐含 | ✅ 同名追问、备注检索、最近对话上下文、相对日期查表；模型拿不准的字段在确认卡上标"核对" |
| 子任务 DAG | ✅ 依赖图校验（无环、依赖存在）；**并行分支**（生日计划里鲜花与蛋糕）；**节点间传递结果**（`{$ref, path}`）；待办页按层画出图 |
| 中断 | ✅ 暂停、停止剩余步骤；新需求自动暂停旧图 |
| 回退 | ✅ **补偿流程**：对已完成步骤按相反顺序生成补偿任务（未付款订单→取消、预算→释放、卡片→反向操作、已付款/已转账→**撤回申请**），每步仍需确认；撤回申请由人工受理，通过才退款，驳回不动资金 |
| 人工接管 | ✅ **人工客服工作台**：多步骤任务、单个草案、对话、风控、撤回申请都能转人工；客服可受理、备注、交还用户（重新生成草案由用户确认）、审批撤回、解除风控、关闭；**没有任何替用户确认付款的入口**。🟡 演示中客服由同一浏览器扮演 |
