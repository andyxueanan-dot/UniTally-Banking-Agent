# 2026-10-02：界面收简与第一轮完整业务评测

这是一次阶段交付，不是“全部赛题已经完成”的声明。仅使用模拟账户；未接真实银行、商户或真实付款。

## 这轮改了什么

- 手机首页只保留余额、助手入口、四个常用入口、三条最近记录；消费图表、卡片详情留在对应页面。
- 服务中心改成目录，选择一项再显示表单；设备验证、技术时间线、消息来源和安全案例默认折叠。不隐藏确认前的收款人、金额或风险提示。
- 助手页独立显示对话和输入框，不重复堆叠任务卡；待确认操作统一进入“待办”。返回助手时定位到最新对话。
- 新增手工“模拟刷卡”流程：更多服务 → 扩展卡服务 → 验证卡片限制。核对卡状态、线上/境外限制、日累计消费限额、可用余额；允许的交易仍走红色确认验证，更新模拟清算及账单。拒绝的交易不扣款。
- 模型无权直接调用这个手工模拟刷卡动作。线上/线下、境内/境外两个维度独立；不将转账当作刷卡。
- 意图提示修复：联系人快照没有所有备注，按备注转账交给后端查找；商户名称不可随意缩短扩大筛选范围。取消订阅缺少范围时明确追问。
- 当前团队目录已安装独立 Wasmtime 49.0.0，原有受限计算测试可运行。仍只有手工/预置 WAT，未完成实时模型生成代码流水线；公网仍禁用计算和 Passkey 接口。

## 真实模型评测：预算和失败均保留

用户明确批准本轮最多 60 次 DeepSeek 调用。现已使用 60/60 次，停止继续调用；供应商报告合计 153,325 tokens。没有根据 token 数自行估算费用。

固定开发集 `evaluation/bank-intents.full.json` 共 36 项，覆盖六类场景、澄清、安全拒绝、受控确认及三步任务。它是自建开发集，不是官方测试或独立盲测。

| 阶段 | 结果 | 解释 |
|---|---|---|
| 首轮真实调用 | 32/36 | 商户名称缩短、备注联系人被提前否定、订阅范围追问类型不一致、工作流尚待显式继续 |
| 定向真实复测 | 23/24 | 修复后复测失败项及部分回归；其中剩余一项是评测脚本错误调用 `resume`，实际 READY 工作流需要 `advance` |
| 工作流离线重放 | 通过 | 用首轮保存的真实模型计划，明确确认转账，再调用正确的 `advance`，达到 SUCCEEDED 且仅一笔扣款。**不是新一次真实模型成功** |

不得将两轮相加计算“整体准确率”，也不能宣称最新全工具真实评测 100% 通过。36 项不是所有业务边界穷举。测试脚本的确认和继续操作模拟用户明确操作，不是模型自动获得授权。

首轮和定向复测原始文件分别保存在工作区 `evidence/T008-quality/model-baseline.json` 和 `model-targeted-rerun.json`。离线重放在 `workflow-replay.json`；授权额度在 `model-budget.json`，这些不放在公开源码中。

评测命令默认 dry-run：`node scripts/evaluate-bank-full.mjs` 不调用 API。`--live --run=<唯一名称>` 会调用供应商并记录已消耗配额；本轮 60 次额度已用完，不能换 run 名绕过配额。新机器不会继承本机额度记录，**必须另获明确授权才能运行 live**。
